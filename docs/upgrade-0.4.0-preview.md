# v0.4.0 升级指南：先把连接配好，再用需要的高级功能

> 本指南沿用预览阶段文件名，避免已有链接失效；内容对应 v0.4.0。正式下载、验收和已知限制见[发布说明](release-v0.4.0.md)。v0.3.1 标签和已发布包不覆盖。

## 普通用户先做这三步

1. 使用对应系统的 v0.4.0 构建，启动后先点「一键检测环境配置」，再看首页的“下一步”。提示缺连接，就填自己已有的代理地址；有多个订阅就直接一行一个粘贴，不必制作 TXT。
2. 确认 Codex 已接管，重启 Codex、新建会话，发一条短消息。能打开面板不代表请求已经接入。
3. 首页保留「拿到后固定使用 · 少探测」。能正常用就先用，不需要研究整张参数表。

已有配置不因为升级强制改成新策略：未写 `state_refresh_mode` 的旧配置保留“提前备好下一份”；想少做探测，在首页主动改为固定使用即可。**切换策略保留当前可用值；修改来源、高级设置或采集时间通常会清空 state。**

## 这次解决什么

| 遇到的问题 | 本版的处理 | 仍然需要注意 |
| --- | --- | --- |
| 不知道配置哪里不对 | 一键只读检测本地环境，需处理项目给「带我去处理」 | 不调用模型、不读凭据内容、不自动修复；上游能力仍未验证 |
| 中转缺少 `base_url`，一键接入失败 | 连接助手只补缺失地址，修改前备份 | 已有地址不强改；key 仍由 Codex / CCS 管理 |
| 长上下文被本地 16 MiB 限制拦成 413 | 请求体、zstd 窗口、压缩回复默认 64 MiB，可调 16–128 MiB | 不提高上游限制，更大上限会占更多内存 |
| 不会准备 TXT，也不会改 JSON | 手动粘贴多个订阅与 TXT 共用导入框 | 先检查再保存，明确追加或替换 |
| 不知道哪些节点已经用过、失败 | 可用 / 已用 / 失败 / 停用清单，支持批量回收 | 记录保留；回收不是解除上游暂停 |
| 只想检查自己选的一个节点 | 现有模型会话中「只试这个节点」 | 每次最多一次短探测，可能计费，尊重冷却 |
| 拿到值后不想反复重新采集 | 新用户默认拿到后固定，失效或不匹配后再获取 | 没有备用时可能等待，不保证零中断 |
| 想把实际出口与采集出口分开 | 高级设置提供独立随机或用户固定 | 实验功能；不同节点不等于不同公网 IP |
| 中转不知道模型名 | 只读 `/models`，筛选 Astra / Sol / Terra | 列表成功不等于生成有权限 |

「提前备好下一份」仍可选。观察到不匹配形状时，不把该响应正文送给客户端；有备用就为下一条请求提升备用。**当前生成可能已计费，不会为了隐藏失败重放请求。** 长度筛选不是回答质量检测，不能保证“不会降智”。

## 原来的默认值哪些没偷偷改

- 默认实际出口仍是兼容模式，跟随采集 state 的节点。新用户默认固定 state，**不等于**默认随机换出口。
- 基础配置默认不启用“用后移出”，保持单代理兼容；但**多订阅导入框默认勾选启用随机出口＋用后移出**，保存前有明确提示。追加时保留已选的固定转发出口；不想启用可取消勾选，也可在高级设置以后调整。
- 个人 / Team 规则不被节点池代替；中转/API 通道不采集、不注入官方 state。
- 401/403 后停止对应凭据的继续尝试；429 遵守上游等待与本地冷却。切换模型、节点、设置或回收不能解除暂停。
- 外部代理模式是可选运行限制，不是已经移除内嵌核心的独立发行版。

## 到哪里拿预览构建

升级分支的 `Preview build` 工作流运行静态检查和竞态测试后，构建 Windows x64/ARM64、macOS Apple Silicon/Intel 四种包，并附带含依赖的源码包及 `SHA256SUMS`。构建产物放在对应 Actions 运行记录的 Artifacts 中，保留 14 天；这不是 GitHub Release，也不会创建正式版本标签。[查看工作流](https://github.com/gylive/ccodex-sleep-state/actions/workflows/preview.yml)

工作流文件存在不代表本次构建已成功；下载前核对对应提交的运行结果与校验文件。未跑完或失败的结果不写成已验收。

## 升级与回退，不动日常配置碰运气

1. 停止旧服务，确认正在生成的请求已经结束、接管配置正常恢复。
2. 保留旧程序和完整的旧数据目录备份。数据目录可能含订阅凭据与配置备份，**不要上传到 Issue 或网盘分享**。
3. 使用独立数据目录和独立 Codex Home 做首次预览测试最稳妥；不要让两版服务同时接管同一个 Codex 配置。
4. 确认预览可用后，再决定是否用于日常环境。遇到问题先下载脱敏诊断，不删除事务记录来消除警告。
5. 回退时先正常停止预览版；若异常退出，先按恢复流程处理接管事务。恢复升级前的服务配置备份，再启动保留的旧程序。不要用旧程序直接猜测新配置字段的含义，也不要覆盖测试期间用户另外修改的 Codex 配置。

池状态保存在服务数据目录的 `pool-state.json`。清理节点是可恢复停用；重新导入同一订阅不会自动重置使用历史。手工删记录也不是修复风控、权限或限流的方法。

## 验收到哪一步

本地回归已覆盖新增状态策略、池记录持久化与并发预留、单节点有界重试、超过旧 16 MiB 边界的合法 gzip/zstd 请求、形状不匹配时阻止正文与不重放、缺失中转地址补全等。最终提交对应的测试与构建结果应以该分支 CI 为准，不借用旧标签的成功记录。

真实中转本轮只确认：`GET /models` 返回 200，列出了 `gpt-6-astra`、`gpt-5.6-sol`、`gpt-5.6-terra`。唯一一次 Sol 短生成请求返回 403 后立即停止，没有继续尝试 Terra/Astra。因此**不宣称真实中转生成已通过，也不宣称观察到了真实 Team 332**。来源、密钥和原始响应不公开。
