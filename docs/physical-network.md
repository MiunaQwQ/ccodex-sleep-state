# macOS 节点连接绕过本机 VPN

`node_network_mode: "physical"` 将本程序到代理服务器的连接绑定到 Wi-Fi / 有线网卡，避免被本机 TUN 的默认路由接管。DNS 使用该物理接口的 DHCP DNS 或 macOS scoped DNS，DNS 查询的 socket 也绑定同一接口；不会使用系统的 VPN DNS，也不会接受 198.18.0.0/15 虚拟地址。连接失败时不回退到系统网络。

在面板的「连接设置 → 高级设置」切换网络模式即可。`node_interface` 留空自动寻找带默认网关、IPv4 地址的 en 系列接口；多网卡用户可明确指定接口。切换 Wi-Fi / 有线网络后重新启动服务，以重新发现接口及 DNS。旧配置缺省沿用 `system`，本地独立包已经设置为 `physical`。

物理连接由 mihomo 的 DialerForAPI 注入，不向订阅添加 interface-name，不改原始节点域名、TLS SNI、证书校验或稳定 ID。测速和正式请求使用同一个 Path。采集规则、固定节点、state 备份和上游暂停策略不因此改变。

此模式控制的是本程序发起的连接。本地 HTTP/SOCKS5 客户端的后续连接仍由该客户端决定。它不修改系统路由、VPN 开关或其他应用设置。当前发现接口功能仅支持 macOS，其他平台会明确报错。

## 2026-09-19 本机验证

- Shadowrocket 保持连接，系统默认路由仍是 utun4。
- 测试 socket 读取 IP_BOUND_IF 得到 15，与 en1 接口索引一致。
- 相同 9 个 AnyTLS 节点：修复前本轮 6 个可达、3 个超时；修复后管理接口最终一轮 9 个可达，737–1391 ms。早一轮日本优化2失败，节点仍可能有间歇问题。
- 测试对 /models 不带登录信息，HTTP 401 证明 HTTPS 链路可达；没有调用模型，没有验证 292 或回答质量。
- 验证服务使用另一端口及独立数据目录，不接管 Codex 配置，没有改动正在使用的旧版服务。

已有回归覆盖 DNS 通过绑定连接发送、虚拟地址拒绝、DNS/连接失败不回退、多地址尝试，以及改变网络模式不改变节点 ID。完整测试、相关包 race 检查、go vet 通过。
