# r18 · 节点连接恢复与发行整理

## 修复与优化

- 修复网络故障后只能通过全局环境接管重建连接的问题：同一连接代次连续两次连接或响应读取失败后，自动重建该节点的代理客户端与 HTTP 连接池。保留票、节点来源及采集状态，后续请求使用新连接。
- 旧连接保留至其在途请求全部结束才释放；并发到达的旧代次错误只触发一次重建。当前请求不自动重发，不增加采集请求或重置预算。重建尝试最短间隔 10 秒，不限制手动打票。
- 取消请求、HTTP 权限拒绝、限流和正常 SSE 业务错误不触发连接重建；节点手动停用和自动采集失败清单仍按原规则处理。
- 日志新增脱敏错误类别、连接/读取阶段、连接代次和重建结果；面板诊断显示对应节点最近的错误及重建次数。
- README 改为 NanSsye 维护的二次开发项目介绍，明确上游 gylive/ccodex-sleep-state，保留历史及 GPL-3.0 许可证。移除旧联系方式、推广内容和旧发行称呼。
- 仓库名称统一为 NanSsye/ccodex-sleep-state。发布包、源码包及 SHA256 校验文件均带 r18 版本号，包内附 VERSION、SOURCE_COMMIT 与本更新说明。

## 下载与升级

Windows 常见电脑选 windows-amd64，ARM 电脑选 windows-arm64；Apple Silicon Mac 选 darwin-arm64，Intel Mac 选 darwin-amd64。完整解压后双击 start.cmd / start.command。程序名开头是两个 c：ccodex-sleep-state。

停止旧程序后再替换文件，保留自己的配置与数据目录。四个平台程序包和源码包均从已提交代码构建，不包含个人节点、订阅、票、口令、配置或日志。

## 验证范围

本地测试覆盖连接恢复、旧请求不中断、旧代理释放、并发去重、重建失败保留原连接、读取中断、取消/429 不重建、脱敏分类，以及票/来源保持和请求不重放。另执行 Go 全量测试、竞态检测、go vet、JavaScript 语法及打包内容检查。

浏览器使用本地模拟上游触发两次连接失败，实际展开诊断并确认连接第 2 代、重建 1 次及原票保留。

macOS arm64 在本机运行验证；Windows 与 Intel Mac 提供交叉编译包，不把编译成功当作真实设备长期稳定性验证。自动重建不能保证远端节点或服务一定恢复。
