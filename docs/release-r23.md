# r23 · 自动打票开关与固定节点锁定

## 更新与优化

- 首页「主用策略」旁新增自动打票开关，「连接设置 → 采集时间与次数」保留同一设置。关闭后立即停止后台定时、缺主票、缺备用、到期、失败、空位和新请求触发的采集。
- 关闭开关不会清空或重建会话。已有主票、备用票、固定节点、轮询进度、失败等待、小时预算及上游暂停记录全部保留；「手动打票 · 随机节点一次」和明确的手动重采仍可单独执行。
- 自动打票关闭且没有主票时，严格模式明确提示先手动打票；普通转发模式仍转发正式请求，但不会从该回复静默收取新票。
- 固定节点改为单点锁定。连接失败或探测超时不会把固定入口标记为失败，也不会切到其它本地节点；后续仍尝试同一入口，允许用户在另一台代理设备中直接切换它自己的上游节点。
- 手动停用固定节点仍会阻止使用；取消固定后，非固定节点继续沿用连接失败隔离、手动恢复和候选轮询规则。
- 包含 r22 的面板刷新位置修复。压缩请求的票据处理和响应模型判断本版本不修改。

## 验证

- 自动调度关闭后不会排队或发出探测，首条正式请求也不会触发引导探测；普通回退响应不会进入票池。
- 关闭状态下手动随机打票仍只发出一次请求，原主票不变，新票按备用规则加入，且不会重新开启自动调度。
- 固定节点连续连接失败时始终只尝试同一入口，不进入失败清单、不访问其它候选；非固定节点的原有失败隔离回归通过。
- 自动打票设置经过管理接口保存、回读、备份和在线生效验证，现有引擎未重建。
- `node --check internal/service/web/app.js`、`go vet ./...`、`go test ./...` 与相关竞态测试通过。
- 浏览器验收只使用本机回环合成数据，不代表真实上游或节点稳定性。

## 下载与升级

发布文件均以 `ccodex-sleep-state-r23-` 开头，覆盖 Mac Apple Silicon / Intel、Windows AMD64 / ARM64，并附源码包及 SHA256 校验文件。包内带版本、源码提交和本更新说明，不包含维护者节点、订阅、票、凭据、口令或运行日志。

停止旧服务后替换程序，保留自己的配置与数据，再通过 `start.cmd` / `start.command` 启动；升级后刷新管理面板。旧配置没有 `automatic_disabled` 字段时继续保持自动打票开启，不会因升级意外关闭。
