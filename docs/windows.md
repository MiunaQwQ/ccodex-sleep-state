# Windows：解压、双击、填代理

不需要安装 Go，也不需要管理员权限。先确认 Codex 原来的登录或中转配置能用；本工具不能代替登录、开通模型或增加额度。

> 这份教程对应当前源码。旧发布包如果没有 `start.cmd` 或 `setup`，请先看对应 Release 说明。Windows 自动测试通过，不等于每一种 Windows 桌面版 Codex 都已实测。[验收边界](issues-and-verification.md)

## 1. 完整解压，不要只拖出 exe

到 [Releases](https://github.com/NanSsye/ccodex-sleep-state-r14/releases) 下载 ZIP。大多数电脑选 `windows-amd64`；Windows ARM 选 `windows-arm64`。核对来源和 `SHA256SUMS`，再完整解压到自己的目录，例如：

```text
%LOCALAPPDATA%\Programs\ccodex-sleep-state
```

文件夹里应有 `ccodex-sleep-state.exe`、`start.cmd` 和教程。路径带空格没关系，不要放在公开共享目录。

发布程序没有商业代码签名。遇到系统拦截，先确认文件来源，不要为了运行它全局关闭 Defender 或 SmartScreen。

## 2. 双击启动

1. 用 CCS / CC Switch 的，先在 CCS 中选好这次要用的配置。
2. 退出 Codex，暂时不要继续切 CCS。
3. 双击 **`start.cmd`**。不是双击 `ccodex-sleep-state.exe`；裸 exe 不带命令只显示帮助。
4. 浏览器自动打开并进入面板，保留终端窗口。
5. 程序会自动接入；显示已接管后重启 Codex，新建会话试一句。不需要再点一次接入。

喜欢用命令行也可以：在解压文件夹地址栏输入 `powershell`，然后运行：

```powershell
.\ccodex-sleep-state.exe setup
```

第一次会创建服务配置，之后再运行会沿用原设置，不需要先 `init`。启动不发送模型请求；接管 Codex 后的真实对话和 state 采集可能消耗额度。

正常情况下不需要复制口令：程序用短期、一次性的启动凭证进入面板，地址里的凭证会立即清除。若浏览器没打开或凭证过期，再使用终端显示的管理地址和口令手动进入。默认地址是 [http://127.0.0.1:17841/admin/](http://127.0.0.1:17841/admin/)。口令每次启动变化，不是 Codex 密码，不要截图发群。

`setup` 自动接入会先备份并尽量保留当前配置；没有配置代理时只检查 `127.0.0.1:7897`、`:7890`、`:10808` 的 SOCKS5 握手，找到后使用，不扫描外部网络、不读取代理账号库。已有订阅、代理、固定出口和模型选择继续保留。首次 `setup` 没有明确兜底策略时采用「采不到 state 时先正常转发」；之前明确选过 `strict` 的会保留，不会把不合格 state 假装成成功。首页「一键接入 Codex」是出现问题时的重新接入/修复入口，点击确认会选择普通转发兜底。

**已经接上了，后面的设置可以先不用动。** 没找到代理、需要填订阅，或要换模型时再看下面。

## 3. 没找到代理，或只有订阅时再填这里

进入「订阅与代理」，选一种连接方式：

| 你的情况 | 怎么填 |
| --- | --- |
| 已经开着 Clash 一类代理软件 | 选本地代理，填写它的 HTTP / SOCKS5 地址 |
| 手里只有订阅链接 | 选订阅链接，粘贴完整 URL |
| 有 YAML 或 URI 列表文件 | 选本地订阅文件，填完整文件路径 |
| 当前网络可以直接访问上游 | 选直连 |

本地代理格式例如 `socks5://127.0.0.1:7897`。**7897 只是例子，以你代理软件里的端口为准。** 这里填地址，不是填 PowerShell 命令。

点「先测试能否读取」，再点「保存并应用」。读取测试只确认配置能读取、解析和构建，不会问模型，也不会自动保存。想测实际连接，到「路由」读出列表后再测试。收到 HTTP 响应和能采到 state 是两回事。

保存来源会替换本服务原来的出口来源，并保留备份；不会修改代理软件或系统代理。订阅和节点密码只留在本机，不要截图分享。

## 4. 选模型，确认接管，再开 Codex

到「连接设置」：

- **默认模型**可选 Astra、5.6 Sol、5.6 Terra。上游没有权限的模型仍会失败，不能靠这个下拉框开通。
- **账号规则**默认自动识别。Team 用户如果没有被正确识别，手动选 Team；不用再去 JSON 改 `baseline_blocks`。
- **没有合格 state 时**首次 `setup` 未设置策略会采用普通转发兜底；之前明确选择的严格策略不被自动覆盖。你可以在这里修改，两种选择都不解除官方限流。
- 确认 **Codex 配置：已接管**，然后重启 Codex，新建会话发一条短消息。

官方 ChatGPT + 开启注入，首条请求可能等待采集。中转 / 官方 API key 通道不采集官方 state，直接转发。关闭注入仍经过本服务和所选出口。

判断是否接通，分开看：

1. 面板能打开：本地服务活着。
2. 已接管：配置入口已接到本工具。
3. 请求计数增加：Codex 请求确实经过这里。
4. 会话有可用 state：本地筛选通过，**不是质量检测通过**。

## 旧版本升级、CCS 报 409，怎么办

先别删配置，也别删 `config-transaction.json`。新版提供了可预览的修复入口：

1. 保留当前文件，关闭其他正在运行的旧版服务。
2. 启动新版，进入面板「连接设置」。
3. 点 **「检查与修复配置」**。
4. 一般选 **「保留当前配置并重新接管」**，让 CCS 当前的选择继续生效。
5. 如果无法安全保留，页面会拒绝操作。只有确认自己要撤销后来的修改，才选 **「恢复接管前备份」**。
6. 完成后重启 Codex，新建会话。

修复会先归档当前配置和恢复记录，再做修改；预览后文件又变了，会要求重新检查。不会因为多点几次按钮就强行覆盖。

现在只改注释或无关设置，不应再触发整个服务的 409；真正换了 provider、上游或认证，仍需检查和重新接管。推荐顺序一直是：**停止服务 → CCS 切换 → 再启动服务 → 重启 Codex**。

### 服务 JSON 写坏了

`setup` 会启动只读修复面板，不加载坏配置里的代理，不修改 Codex，不发送模型请求。点「检查并重建服务配置」，阅读说明后确认：

- 原 JSON 先备份到本工具数据目录的 `backups`。
- 生成新的默认服务配置，注入先关闭。
- 停止修复服务，再运行 `setup`。
- 原订阅不会自动从损坏文件里猜出来；需要从本机备份核对后重新填写。

### Codex TOML 本身坏了

这是另一份文件，别和服务 JSON 混在一起。优先让 CCS 重新生成你要用的配置；使用面板的备份重建入口时，必须明确选择原来的登录方式与上游。备份会保留，但新的最小配置不会保留坏 TOML 里所有偏好设置。

不确定原来用的是官方还是中转，就先停止，不要把官方登录凭据拿去试未知地址。不要删除 `auth.json` 或整个 `.codex`。

## 不会排查，发一份诊断就够了

面板「遇到问题」可以下载脱敏诊断。也可以另开 PowerShell，在程序目录执行：

```powershell
.\ccodex-sleep-state.exe doctor
```

它只读状态，不调用模型，不输出订阅、代理密码、管理口令、登录信息或聊天正文。把结果连同系统版本、Codex 版本和工具版本发给群友或 AI Agent。若运行了多个独立数据目录，`doctor` 要带上对应 `--data-dir`。

不要发整个数据目录。备份文件虽然有助于恢复，也可能包含你的私人配置。

## 停止、恢复和卸载

正常停止：回到服务窗口按 **Ctrl+C**，等恢复完成，再重启 Codex。尽量先等当前回复结束。关闭浏览器不会停止服务；关闭注入不会恢复 Codex 配置。

只想恢复而不继续运行，先确认服务已经退出，再执行：

```powershell
.\ccodex-sleep-state.exe restore
```

如果提示冲突，回到上面的面板修复流程，不要反复删除文件。卸载前先恢复配置，然后再处理本工具的程序和数据目录。程序没有安装 Windows 后台服务或开机自启，下次用时仍需启动。

## 文件在哪，以及高级用法

```powershell
.\ccodex-sleep-state.exe paths
.\ccodex-sleep-state.exe version
```

默认服务配置在 `%LOCALAPPDATA%\ccodex-sleep-state\config.json`，日志在同目录的 `logs`，默认 Codex 配置在 `%USERPROFILE%\.codex\config.toml`。设置过 `CODEX_HOME` 或独立数据目录时，以 `paths` 输出为准。

只试面板，不接管日常 Codex：

```powershell
.\ccodex-sleep-state.exe setup --data-dir "$env:LOCALAPPDATA\ccodex-trial" --no-config
```

`--no-config` 不接管 Codex，面板的接管/修复按钮也不会偷偷绕过它。需要接入时停止服务，去掉该选项再启动。**它不是禁止联网**：已有订阅可能下载，手动连接测试也会联网。

手改 JSON 的用户，应先停服务，修改后执行 `check`，再重新启动。`check` 不请求模型，但可能下载订阅。通常用面板更省事，不需要手改。
