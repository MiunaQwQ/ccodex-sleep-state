# r21 · 紧凑对话卡片与请求结束诊断修复

## 更新与优化

- 对话请求改为紧凑小卡片：桌面三列、窄屏两列、手机单列；折叠展示模型、状态、收到/返回/失败/取消次数和实际节点，展开查看完整明细。
- 无在途请求且空闲 10 分钟后自动移出页面；在途请求不会因耗时长被清理。新增右上角 × 手动移除，刷新仍隐藏，有新请求重新显示。
- 清理仅影响页面展示，保留本次启动的诊断统计，不停止请求、不丢弃主票或备用票。手动移除保存在当前浏览器；按请求活动判断空闲，不能直接判断客户端任务是否永久结束。
- 修复「完整返回后被误记为取消」：旧逻辑优先检查连接关闭，且要求上游 socket EOF，可能覆盖已经转发的 response.completed。现在记录完成事件的字节边界，只有成功完整写出后才计为完成；后续关闭连接显示「完整返回后关闭连接」。
- 保留上游明确失败，不让随后的客户端断开将其覆盖为取消。分别显示客户端中途断开、请求超时、服务停止、上游失败、响应流中断和写回失败；仅解析到但未写出的完成事件不算成功。
- 日志和请求明细增加完成事件观察/转发证据及结束原因，便于区分真实中断与正常收尾。保持票据采集验证规则，不改变转发正文，不自动重放请求。

## 验证

- 通过完整 Go 测试、go vet、gateway/service/turnstate race 检查与 JavaScript 语法检查。
- 回归覆盖完成事件后立即关闭连接、未完成时断开、上游失败后断开、部分写出、分字节 SSE/CRLF、完成后尾部写出失败、请求超时和服务停止。
- 合成数据浏览器验收：折叠卡片约 164 像素高，展开显示返回原因；手动移除及刷新保持、新请求重现、模拟超过 10 分钟的空闲卡片清理、在途卡片保留及手机布局均通过。
- 历史 r20 记录缺少结束事件证据，不能据此断言每一条历史取消都是误判。Windows 与 Intel Mac 提供交叉编译包，本次未在这些实机运行验收。
