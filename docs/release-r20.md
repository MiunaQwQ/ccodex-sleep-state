# r20 · 对话请求追踪与保留主票切换节点

## 新增与优化

- 新增「对话请求」：按客户端对话标识区分真实对话，同模型不同对话分开显示；旧的模型卡片明确称为「模型票池」，同账号同模型仍共用主备票。
- 请求到达立即计数，无需等回复结束。支持本地处理中、已发起上游请求、正在返回、完整返回、失败、取消及未确认完成；HTTP 200 不再被误读为生成成功。
- 每个对话可展开看请求类型、请求/响应模型、实际出站节点、是否注入主票、耗时、响应头时间及向客户端写出的字节数。自动审批和远程压缩分别标记；没有有效对话标识的请求明确列为未识别。
- 主票旁新增「切换节点」：保留同一张票，在可用节点中手动选择新的出口，并区分原始采集来源和当前出站。切换保存到本地，生成与 V1/V2 压缩都使用当前节点；原采集节点移出池后，重启仍保留新节点上的主票及来源标识。
- 切换不发送探测、不延长有效期、不修改备用票、采集预算或账号限制，不自动重放请求。在途请求保留旧快照，旧节点的迟到响应不能使切换后的主票失效；新的主票失效仍按原有主备规则处理。
- 并发面板或过期主票操作会拒绝陈旧版本；保存失败不会发布切换结果。切换影响共用该账号、该模型票池的后续带票请求。

## 验证

- 完整 Go 测试、go vet，以及 gateway/service/turnstate 的 race 检查通过。
- 合成上游测试覆盖到达即显示、响应头前与流式返回阶段、同账号不同对话隔离、跨账号隔离、本地拦截、取消、HTTP 200 未完整结束、私密正文不进入记录。
- 覆盖保留原票切换实际传输节点、生成与压缩带票、在途旧节点迟到失败、备用票和账号隔离、保存失败回滚、重启恢复、旧版本及停用节点拒绝。
- 合成数据浏览器验证完成：主票切换按钮、选择节点并提交、保留主票和备用票、显示原始来源，以及展开对话查看在途和完成记录。
- Windows 和 Intel Mac 提供交叉编译产物；本次未在这些实机上运行验收。合成测试不代表任意代理节点或上游均接受跨节点使用同一票。

## 记录范围与升级

对话记录仅含本机内存中的元数据，重启会清空；保留最近 128 个分组、每组 50 条结束记录以及所有在途请求。无有效对话 UUID 时不能可靠区分真实对话，不根据正文猜测。响应模型仅为上游声明。

完整解压对应的 `ccodex-sleep-state-r20-<系统>-<架构>` 包，使用 start.cmd / start.command。升级前停止旧进程，保留个人配置与数据。包内附版本、源码提交、更新说明，发布附件不包含维护者节点、订阅、票、凭据、管理口令或日志。
